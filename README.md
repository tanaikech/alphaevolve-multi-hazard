## 1. Role and Positioning of AlphaEvolve in This Research

Traditional geophysical hazard warning systems treat meteorological downbursts, pre-seismic crustal anomalies, and volcanic infrasonic shockwaves as isolated domains relying on disconnected heuristic rules. When deployed concurrently on dense citizen-science IoT weather sensor networks, single-threshold heuristics suffer from cross-hazard interference—most notably triggering false alarms during non-convective winter/spring synoptic windstorms (bomb cyclones) or urban heat island fluctuations. Conversely, conventional deep learning approaches act as opaque "black boxes" that cannot yield explicit mathematical equations or guarantee zero false alarms on out-of-distribution weather regimes.

In this study, **AlphaEvolve** (powered by **Gemini 3.8 Flash**) serves as an **autonomous symbolic code-discovery engine** operating within a closed-loop Popperian falsification architecture:

   Instead of optimizing millions of opaque neural network weights, AlphaEvolve iteratively mutates explicit Python mathematical functions enclosed between `# EVOLVE-BLOCK START` and `# EVOLVE-BLOCK END`. Every candidate algorithm remains 100% human-readable, deterministic, and physically interpretable.
2. **Strict Anti-Tampering & Popperian Falsification Gauntlet (3-Tier Defense)**:
   - **Tier 1 (AST Static Security Gate)**: Inspects the Python Abstract Syntax Tree (AST) before execution and immediately rejects any candidate code that imports forbidden modules (`random`, `os`, `sys`, `subprocess`, `pickle`, `time`), invokes dynamic evaluators (`eval`, `exec`, `open`, `__import__`), calls pseudo-random number generators (`np.random`), or hardcodes historical event dates or sensor MAC prefixes ($\text{Fitness} = -10^{12}$).
   - **Tier 2 (Double-Run Determinism & Read-Only Sandbox)**: All pre-computed physical feature tensors are sealed in read-only memory (`flags.writeable = False`). Each candidate function is executed twice on identical physical inputs inside an isolated namespace to verify exact floating-point determinism ($|y_1 - y_2| < 10^{-12}$) and valid physical bounds.
   - **Tier 3 (Popperian Falsification Penalty)**: Candidates are evaluated across 21 historical disaster events (15 convective rainstorms, 4 major earthquakes, 2 volcanic eruptions) and 2 challenging non-disaster control baselines (a calm winter day and an explosive spring bomb cyclone). ### 1.1 Where and How AlphaEvolve Is Used in the Scripts

In this codebase, AlphaEvolve is implemented through the closed-loop interaction of three core components:

1. **Target Evolution Block (`SEED_PROGRAM` in [`scripts/03_defensive_evaluator.py`](scripts/03_defensive_evaluator.py#L36-L90))**:
   - Lines 36–90 define the baseline Generation 0 heuristic program (`SEED_PROGRAM`).
   - The four Python functions enclosed between `# >>>>>>>>>>>>>>>>>>>>>>>> # EVOLVE-BLOCK START <<<<<<<<<<<<<<<<<<<<<<<<<<<<` and `# EVOLVE-BLOCK END` (`compute_rain_convective_score`, `evaluate_laic_and_gate`, `compute_volcanic_semblance_threshold`, and `dispatch_hazard_decision`) constitute the mutable search space that AlphaEvolve iteratively rewrites.
2. **3-Tier Evaluator & Diagnostic Feedback Engine ([`scripts/03_defensive_evaluator.py`](scripts/03_defensive_evaluator.py#L230-L388))**:
   - `DefensiveEvaluatorHarness.evaluate(code_str)` (lines 230–388) receives each mutated Python code string, verifies AST safety (`tier1_ast_scan`, lines 162–166) and double-run determinism (`tier2_contract_and_determinism_test`, lines 169–202), and executes the candidate functions against all 23 cached multi-hazard feature tensors.
   - It returns both the scalar **Popperian fitness score** (`fitness`) and structured **diagnostic failure insights** (`insights`, e.g., `CONTROL_FALSE_POSITIVE_RAIN`, `CONTROL_FALSE_POSITIVE_EQ`, `RAIN_MISS`) pinpointing which event failed and why.
3. **Evolutionary Loop & LLM Mutation Operator ([`scripts/04_run_alphaevolve_discovery.py`](scripts/04_run_alphaevolve_discovery.py#L40-L246))**:
   - `extract_evolve_block()` and `replace_evolve_block()` (lines 69–79) isolate and swap the code inside `# EVOLVE-BLOCK`.
   - `_mutate_via_llm()` (lines 81–120) acts as the **AlphaEvolve LLM mutation operator**: it prompts **`gemini-3.8-flash`** (via the `google-genai` SDK) with the current best `# EVOLVE-BLOCK` code alongside the evaluator's diagnostic `insights`, instructing the model to synthesize improved mathematical expressions that eliminate false alarms and missed detections. (When run offline without `GEMINI_API_KEY`, `_mutate_via_symbolic_operator()` on lines 122–177 reproduces this exact structural progression deterministically.)
   - `run_campaign()` (lines 179–246) manages the multi-generation evolutionary loop:
     1. **Generation 0**: The baseline `SEED_PROGRAM` triggers false alarms on the calm winter day and spring bomb cyclone control baselines, incurring $-5,000 \times 2 = -10,000$ in penalties ($\mathcal{F} = -9600.03$).
     2. **Guided Mutation & Selection**: Guided by `CONTROL_FALSE_POSITIVE_RAIN` and `CONTROL_FALSE_POSITIVE_EQ` insights, AlphaEvolve introduces the cold-airmass gate ($\theta_e < 332.0\text{ K}$, jumping fitness to $\mathcal{F} = -4600.02$) and the quasi-isobaric LAIC gate ($|dP/dt| \le 2.0\text{ hPa/h}$, jumping fitness to $\mathcal{F} = +399.98 / 400.0$).
     3. **Champion Export**: The discovered optimal code is saved as [`scripts/evolved_hazard_dispatcher.py`](scripts/evolved_hazard_dispatcher.py) and verified across all 23 events by [`scripts/05_verify_multi_hazard_prediction.py`](scripts/05_verify_multi_hazard_prediction.py).

## 3. Detailed Description of Scripts

### 1. [`scripts/01_generate_sample_data.py`](scripts/01_generate_sample_data.py) — Sample Multi-Hazard Dataset Generator
Because the full multi-year raw Netatmo IoT archive (175,363 records, ~947 MB) is too large to bundle directly in a code repository, this script generates a lightweight, self-contained set of **23 synthetic/virtual sample CSV files** in `sample_data/` (2,430 station-time observations) along with `sample_data/data_manifest.json`. Please note that **this generated sample data is virtual demonstration data and differs from the actual empirical Netatmo sensor observations analyzed in the study**, though it is mathematically constructed to emulate the characteristic thermodynamic and acoustic regimes of the 23 benchmark events:
- **15 Convective Rainstorms (`sample_data/rain/`)**: Warm, high-$\theta_e$ boundary layers ($\theta_e > 345\text{ K}$) undergoing rapid evaporative downdraft cooling ($d\theta_e/dt < -10\text{ K/h}$), mesoscale pressure drops ($\Delta P_{10\text{min}} > 2.0\text{ hPa}$), and cold-pool gust surges.
- **4 Major Earthquakes (`sample_data/earthquake/`)**: Dense 36-station regional arrays under quasi-isobaric synoptic conditions ($|dP/dt| \le 0.6\text{ hPa/h}$) exhibiting localized epicentral thermal anomalies ($\delta\theta_e > 42\text{ K}$, $\text{LPAR} > 6.0$).
- **2 Volcanic Eruptions (`sample_data/volcano/`)**: Multi-station barometric arrays recording coherent acoustic Lamb wave pulses ($c_{\text{app}} \in [310.6, 319.2]\text{ m/s}$, semblance $S > 0.91$).
- **2 Popperian Control Baselines (`sample_data/control/`)**:
  - `control_01_quiet_20180115`: A calm winter day with minor urban heat island variance ($\delta\theta_e \approx 9.5\text{ K}$, $\text{LPAR} \approx 2.9$) that causes naive earthquake thresholds to fire false alarms.
  - `control_02_stormy_20180301`: A severe non-convective spring bomb cyclone ($\theta_e \approx 306\text{ K} < 332\text{ K}$, $|dP/dt| \approx 6.4\text{ hPa/h}$, strong wind gusts) that causes naive rain and earthquake rules to fire false positives.

### 2. [`scripts/02_extract_physics_features.py`](scripts/02_extract_physics_features.py) — First-Principles Physics Feature Extractor
Reads `sample_data/data_manifest.json` and computes first-principles physical features for each hazard category:
- **Bolton (1980) Equivalent Potential Temperature ($\theta_e$)**: Exact non-linear thermodynamic formulation from temperature ($^\circ\text{C}$), relative humidity ($\%$), and sea-level pressure ($\text{hPa}$), with quality control filtering indoor heating outliers ($|T - \text{median}(T)| \le 6.0^\circ\text{C}$).
- **Convective Kinematics**: Cooling rate $d\theta_e/dt$ ($\text{K/h}$), 10-minute pressure drop $\Delta P_{10\text{min}}$ ($\text{hPa}$), and wind gust ratio $W(t)/\overline{W}$.
- **LAIC Spatial Residuals**: 30-minute spatial median subtraction $\delta\theta_{e,i}(t) = \theta_{e,i}(t) - \text{median}_j[\theta_{e,j}(t)]$, regional standard deviation $\sigma_R(t)$, Local Precursor Anomaly Ratio $\text{LPAR}(t) = \max_i[\delta\theta_{e,i}(t)] / \sigma_R(t)$, and synoptic barometric tendency $|dP/dt|$ ($\text{hPa/h}$).
- **Volcanic Acoustic Features**: Active station count $N$, signal-to-noise ratio $\text{SNR}$, multi-station semblance coherence $S(\mathbf{s})$, and apparent TDOA moveout velocity $c_{\text{app}}$ ($\text{m/s}$).
- **Read-Only Memory Seal**: Locks every NumPy feature matrix with `feat_matrix.flags.writeable = False` and writes `.pkl` caches to `sample_data/processed_cache/`.

### 3. [`scripts/03_defensive_evaluator.py`](scripts/03_defensive_evaluator.py) — 3-Tier Defensive Evaluator Harness
Implements `DefensiveEvaluatorHarness` and `SecurityASTVisitor`:
- Evaluates any candidate Python string across Tier 1 (AST static security check), Tier 2 (double-run floating-point determinism $|y_1 - y_2| < 10^{-12}$ and physical bound check), and Tier 3 (23-event benchmark with the $-5,000$ point Popperian false-alarm penalty).
- When run with `--test-harness`, it executes a 4-stage self-test verifying:
  1. The baseline `SEED_PROGRAM` receives a negative score ($\mathcal{F} \approx -9600.03$) due to false alarms on the control days, whereas `scripts/evolved_hazard_dispatcher.py` achieves $\mathcal{F} \approx 399.97 / 400.0$ with zero issues.
  2. Injected `np.random.normal` calls are blocked by Tier 1 AST inspection ($\mathcal{F} = -10^{12}$).
  3. Injected hardcoded historical event dates (`"2018-01-23"`) are blocked by Tier 1 AST inspection ($\mathcal{F} = -10^{12}$).
  4. Injected forbidden module imports (`import time`) are blocked by Tier 1 AST inspection ($\mathcal{F} = -10^{12}$).

### 4. [`scripts/04_run_alphaevolve_discovery.py`](scripts/04_run_alphaevolve_discovery.py) — AlphaEvolve Evolutionary Discovery Runner
Executes the evolutionary loop starting from `SEED_PROGRAM`:
- **LLM Mutation Mode**: When `GEMINI_API_KEY` is provided in the environment, the script queries `gemini-3.8-flash` via the `google-genai` SDK, feeding diagnostic failure insights from the evaluator to mutate the code inside `# EVOLVE-BLOCK`.
- **Deterministic Symbolic Fallback Mode**: When run offline without an API key, the script automatically uses its built-in symbolic mutation operator so users can reproduce the exact step-by-step fitness trajectory ($\mathcal{F}: -9600.03 \to -4600.02 \to +399.98$) and saves the log to `results/evolutionary_trajectory.json`.

### 5. [`scripts/05_verify_multi_hazard_prediction.py`](scripts/05_verify_multi_hazard_prediction.py) & [`scripts/evolved_hazard_dispatcher.py`](scripts/evolved_hazard_dispatcher.py) — Benchmark Verification CLI
Loads the discovered unified dispatcher (`scripts/evolved_hazard_dispatcher.py`), evaluates it across all 23 cached events in `sample_data/processed_cache/`, prints the complete event-by-event verification table, and writes:
- `results/multi_hazard_prediction_results.json`
- `results/verification_report.md`

## 4. Step-by-Step Usage Instructions

All commands below should be run directly from the root of this repository (`alphaevolve-multi-hazard/`):

### 1. Install Dependencies

```bash
pip install -r requirements.txt
```

### 2. Generate the Sample Multi-Hazard Datasets (Optional: Pre-Generated in `sample_data/`)

```bash
python3 scripts/01_generate_sample_data.py
```

### 3. Extract First-Principles Physics Features & Lock Cache

```bash
python3 scripts/02_extract_physics_features.py
```

### 4. Run the 3-Tier Defensive Evaluator Self-Test Suite

```bash
python3 scripts/03_defensive_evaluator.py --test-harness
```

### 5. Run the AlphaEvolve Evolutionary Discovery Campaign

To run in offline deterministic symbolic mode:
```bash
python3 scripts/04_run_alphaevolve_discovery.py --generations 10
```

To run with live `gemini-3.8-flash` API mutations:
```bash
export GEMINI_API_KEY="your-gemini-api-key"
python3 scripts/04_run_alphaevolve_discovery.py --generations 50 --model gemini-3.8-flash
```

### 6. Run Full 23-Event Multi-Hazard Benchmark Verification

```bash
python3 scripts/05_verify_multi_hazard_prediction.py --eval-all
```
